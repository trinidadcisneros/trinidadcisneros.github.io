Key Insight: Hard Errors vs. Silent Errors
Hard Errors (you see a traceback): Easy to catch during testing. Stop execution. Examples: TypeError, KeyError, ValueError.

Silent Errors (code runs, result is wrong): Harder to catch—no traceback to alert you. Must inspect data with .shape, .head(), .dtypes. Examples: merge fan-out, dtype coercion, NaN propagation. Interview focus: Interviewers love testing if you check dimensions and dtypes before declaring code correct.
Reading Tracebacks

The Golden Rule: Read Bottom-Up

Python tracebacks look scary. They're not. They tell a linear story of where your code broke. Always read the last 3 lines first.

The 3-Second Read

  1. Error Type (last line): What went wrong? TypeError, KeyError, ValueError?
  2. Error Message (last line): Why did it go wrong? This is gold.
  3. The Code Line (in the traceback): Which line of your code caused it?

Real Example Traceback

Traceback (most recent call last): File "analysis.py", line 42, in <module> result = df['name'] + 5 ~~~~~~~~~~~~^~~ TypeError: unsupported operand type(s) for +: 'str' and 'int'

Labeled Breakdown

  • Traceback (most recent call last): — Start here, then read DOWN.
  • File "analysis.py", line 42 — Your code, line 42.
  • result = df['name'] + 5 — The exact code that broke.
  • TypeError: — Error type (not a KeyError, not a ValueError).
  • unsupported operand type(s) for +: 'str' and 'int' — The why: you tried to add a string to an int.

Interview Tip: Read Errors Out Loud
In a real interview, say the error message out loud after you see it. Don't stare silently.

Bad: Stare at the screen for 10 seconds.
Good: "I see a TypeError on line 42. It says I'm trying to add a string to an integer. That's because the 'name' column is text, not numeric."

This shows confidence and gives the interviewer insight into your thinking.
Type Errors

You tried to do something with incompatible types.

A1: String + Integer
▼

Trying to add an integer to a string column

Error:
TypeError: unsupported operand type(s) for +: 'str' and 'int'
Broken Code:
import pandas as pd df = pd.DataFrame({'name': ['Alice', 'Bob'], 'age': [30, 25]}) result = df['name'] + 5 # Trying to add int to string column
Explanation:

You're treating a string column like a numeric column. Pandas preserves dtypes strictly.

Fix:
# If you meant to concatenate: convert to string result = df['name'] + df['age'].astype(str) # If you meant to add: convert name to numeric result = pd.to_numeric(df['name'], errors='coerce') + 5
A2: Wrong Argument Type to Function
▼

Function signature expects different argument types

Error:
TypeError: merge() got an unexpected keyword argument
Explanation:

The function signature expects certain arg types. You passed something it doesn't accept.

Fix:
# Read the function signature import pandas as pd help(pd.merge) # Correct usage: df_left.merge(df_right, left_on='id2', right_on='id', how='outer')
A3: Calling .columns as Function
▼

.columns and .index are attributes, not methods

Error:
TypeError: 'Index' object is not callable
Broken Code:
cols = df.columns() # Wrong: .columns is an attribute
Fix:
cols = df.columns # Correct: no parentheses
A4: Unsupported Operation Between Types
▼

Trying to perform an operation on incompatible types

Error:
TypeError: unsupported operand type(s) for -: 'str' and 'str'
Fix:
# Check dtype first print(df.dtypes) # Convert to numeric if needed df['amount'] = pd.to_numeric(df['amount_str'])
Key & Index Errors

You tried to access a column or row that doesn't exist.

B1: Column Name Typo
▼

Column doesn't exist; maybe a typo in the name

Error:
KeyError: 'naem'
Broken Code:
df = pd.DataFrame({'name': ['Alice', 'Bob'], 'age': [30, 25]}) print(df['naem']) # Typo: 'naem' instead of 'name'
Fix:
# Always check column names first print(df.columns) # Use the correct name print(df['name'])
B2: Column Changed After Rename or Merge
▼

Column name changed; you're using the old name

Error:
KeyError: 'user_id'
Fix:
# Always check columns after transformations df = df.rename(columns={'user_id': 'customer_id'}) print(df.columns) # Now 'customer_id' exists # For merge: specify suffixes df = df_orders.merge(df_users, on='id', suffixes=('_order', '_user'))
B3: Using String Label with iloc
▼

iloc uses integer positions; .loc uses labels

Error:
TypeError or KeyError
Broken Code:
df = pd.DataFrame({'a': [1, 2, 3], 'b': [4, 5, 6]}) value = df.iloc['a'] # Wrong: iloc expects integer position
Fix:
# Use .loc for labels value = df.loc[:, 'a'] # Or use .iloc with integer position value = df.iloc[:, 0] # First column
B4: MultiIndex or Hierarchical Columns
▼

Accessing columns in a MultiIndex DataFrame

Fix:
# Access with tuple value = df[('A', 'x')] # Check structure print(df.columns)
Value Errors

The value you provided doesn't match the operation's requirements.

C1: Length Mismatch When Assigning Column
▼

New column has different length than DataFrame

Error:
ValueError: Length of values (5) does not match length of index (10)
Fix:
# Make sure values match DataFrame length new_values = [10, 20, 30, 40, 50] # 5 values for 5 rows df['amount'] = new_values # Or use a Series with matching index df['amount'] = pd.Series([10, 20, 30, 40, 50], index=df.index)
C2: Cannot Convert String to Float
▼

String contains special characters preventing conversion

Error:
ValueError: could not convert string to float: '$1,234.56'
Fix:
# Remove non-numeric characters first df['price'] = df['price_str'].str.replace('$', '').str.replace(',', '') df['price'] = pd.to_numeric(df['price']) # Or use errors='coerce' df['price'] = pd.to_numeric(df['price_str'], errors='coerce')
C3: Pivot Duplicates
▼

Pivot has duplicate index values

Error:
ValueError: Index contains duplicate entries, cannot reshape
Fix:
# Aggregate duplicates first df = df.groupby(['date', 'product'])['sales'].sum().reset_index() pivot = df.pivot(index='date', columns='product', values='sales') # Or use pivot_table (handles duplicates) pivot = df.pivot_table(index='date', columns='product', values='sales', aggfunc='sum')
C4: Concat Mismatched Index
▼
Fix:
# Reset index to avoid overlap result = pd.concat([df1, df2], ignore_index=True)
Copy Warning Errors

You're modifying a view instead of a copy.

D1: Chained Indexing
▼

SettingWithCopyWarning from chained indexing

Warning:
SettingWithCopyWarning: A value is trying to be set on a copy of a slice from a DataFrame.
Broken Code:
df[df['salary'] > 55000]['salary'] = df[df['salary'] > 55000]['salary'] + 1000 # WARNING!
Fix:
# Use .loc[] for unambiguous assignment df.loc[df['salary'] > 55000, 'salary'] += 1000
D2: Modifying Slice Without .copy()
▼

Attempting to modify a filtered view

Broken Code:
subset = df[df['a'] > 2] # Creates a view subset['b'] = subset['b'] * 2 # Trying to modify the view
Fix:
# Use .copy() for explicit copy subset = df[df['a'] > 2].copy() subset['b'] = subset['b'] * 2 # Or use .loc[] directly on original df df.loc[df['a'] > 2, 'b'] = df.loc[df['a'] > 2, 'b'] * 2
D3: Assigning to Filtered DataFrame
▼
Fix:
# Always use .copy() or .loc[] filtered = df[df['x'] > 2].copy() filtered['y'] = 999 # Or modify original df with .loc[] df.loc[df['x'] > 2, 'y'] = 999
Merge Errors

This is where silent data corruption happens.

E1: Fan-Out — More Rows After Merge
▼

Row count increased unexpectedly after merge

Silent Error: Row count increased due to duplicate keys. Fix:
# Check key uniqueness BEFORE merging print(df_products['product_id'].value_counts()) # Aggregate duplicates before merge df_products_clean = df_products.drop_duplicates(subset=['product_id']) result = df_products_clean.merge(df_purchases, on='product_id') # Verify row count print(len(result))
E2: NaN in Join Keys (Silent Mismatch)
▼

NaN values don't match, even to other NaN

Silent Error: Result has fewer rows than expected. Fix:
# Check for NaN in join keys print(df_left['id'].isna().sum()) # Fill NaN with a sentinel value before merging df_left['id'] = df_left['id'].fillna(-999) df_right['id'] = df_right['id'].fillna(-999) result = df_left.merge(df_right, on='id')
E3: Dtype Mismatch in Join Keys
▼

Left key is int, right key is float; no match

Silent Error: Merge result has 0 rows. Fix:
# Check dtypes BEFORE merge print(df_left.dtypes) print(df_right.dtypes) # Convert to same dtype df_left['id'] = df_left['id'].astype('int64') df_right['id'] = df_right['id'].astype('int64') result = df_left.merge(df_right, on='id')
E4: Overlapping Column Names
▼

Result has confusing _x and _y suffixes

Fix:
# Specify suffixes explicitly result = df_orders.merge(df_customers, on='id', suffixes=('_order', '_customer')) print(result.columns)
Shape Errors

Confusion about rows vs columns or Series vs DataFrame.

F1: DataFrame vs Series (Single vs Double Brackets)
▼

Result has unexpected dimensions (1D vs 2D)

Example:
df = pd.DataFrame({'a': [1, 2, 3], 'b': [4, 5, 6]}) # Single brackets: returns a Series (1D) series = df['a'] print(series.shape) # (3,) # Double brackets: returns a DataFrame (2D) df_slice = df[['a']] print(df_slice.shape) # (3, 1)
Fix:
# If you want a DataFrame with one column df_one_col = df[['a']] # If you want a Series series = df['a']
F2: axis=0 vs axis=1 Confusion
▼

Applied function to wrong dimension

Example:
import numpy as np df = pd.DataFrame({'a': [1, 2, 3], 'b': [4, 5, 6]}) # axis=0: operate on rows (sum each column) result = df.apply(np.sum, axis=0) # axis=1: operate on columns (sum each row) result = df.apply(np.sum, axis=1)
Fix:
# Be explicit about axis # axis=0: rows (operate on each column separately) # axis=1: columns (operate on each row separately) result = df.apply(np.sum, axis=1) # Sum across rows
F3: Boolean Indexing Returns Series
▼
Example:
df = pd.DataFrame({'x': [1, 2, 3], 'y': [10, 20, 30]}) # Single column: returns Series single = filtered['y'] # If you need DataFrame: single_df = filtered[['y']] # Returns DataFrame
F4: Transposing Confusion
▼
Example:
df = pd.DataFrame({'a': [1, 2, 3], 'b': [4, 5, 6]}) # Original: 3 rows, 2 cols print(df.shape) # (3, 2) # Transposed: 2 rows, 3 cols df_T = df.T print(df_T.shape) # (2, 3)
Silent Data Errors

Code runs, no error, but your data is quietly wrong.

G1: dtype Coercion (int Becomes float with NaN)
▼

Int column automatically becomes float when NaN introduced

Silent Error: int column automatically becomes float. Example:
import numpy as np df = pd.DataFrame({'count': [1, 2, 3, 4, 5]}) print(df['count'].dtype) # int64 # Add a NaN somewhere df.loc[2, 'count'] = np.nan print(df['count'].dtype) # float64 (changed!)
Fix:
# Use nullable integer type df['count'] = df['count'].astype('Int64') # Note capital 'I' # Or fill NaN before operations df['count'] = df['count'].fillna(-1).astype('int64')
G2: Object dtype Hiding Mixed Types
▼

Column has mixed types (strings and ints)

Silent Error: Column has mixed types. Example:
df = pd.DataFrame({'id': [1, '2', 3, '4']}) print(df['id'].dtype) # object (not int)
Fix:
# Check dtype print(df.dtypes) # Convert all values to same type df['id'] = pd.to_numeric(df['id'], errors='coerce')
G3: NaN Propagation in Operations
▼

NaN in calculations propagates to entire result

Silent Error: NaN propagates to results. Fix:
# Fill NaN before operations result = df['a'].fillna(0) + df['b'] # Or use skipna in aggregations total = df.sum(skipna=True) # Ignores NaN
G4: String Accessor on Non-String Columns
▼
Example:
df = pd.DataFrame({'id': [1, 2, 3]}) result = df['id'].str.upper() # Error: id is int, not string
Fix:
# Convert to string first result = df['id'].astype(str).str.upper()
G5: Groupby Dropping NaN Groups
▼
Silent Error: NaN groups are silently dropped. Fix:
# Include NaN group result = df.groupby('category', dropna=False)['value'].sum() print(len(result)) # Now includes NaN group
Import Errors

The package isn't installed, or you imported it wrong.

H1: ModuleNotFoundError
▼

Package not installed in your environment

Error:
ModuleNotFoundError: No module named 'pandas'
Fix:
pip install pandas
H2: Wrong Function Name or Capitalization
▼

Function name is wrong or case-sensitive

Error:
ImportError: cannot import name 'read_csv' from 'pandas'
Fix:
# Check function name (case-sensitive) import pandas as pd df = pd.read_csv('file.csv') # Correct
H3: Pandas Version Conflicts
▼
Example:
# Old Pandas (< 2.0) df = df.append(new_row) # Deprecated # New Pandas (2.0+) df = pd.concat([df, new_row]) # New way
Fix:
# Check Pandas version import pandas as pd print(pd.__version__) # Use compatible code df = pd.concat([df, new_row], ignore_index=True)
Code Review Checklist

Use this 3-pass approach.

Pass 1: Structure

Checkpoint Question What to Look For
Imports All at top? import pandas as pd before use
Naming Descriptive? df_orders not df1
Comments Complex steps explained? "Merge orders with customer info"
Functions Modular (not 500 lines)? Each function does one thing

Pass 2: Logic

Checkpoint Question What to Look For
Merge type Is how= correct? how='left' to preserve rows
Merge keys Keys checked for uniqueness? No fan-out happening
Merge dtypes Same dtype? int vs float mismatch detected
Groupby NaN handling? NaN groups explicitly handled
Dtypes Checked before operations? .dtypes inspected

Pass 3: Verification

Checkpoint Question
Row counts Verify before/after?
Shape Result shape validated?
NaN in key cols Key columns NaN-free?
Interview Tip: Point Out Issues Specifically
Bad: "Looks good." [silence]
Good: "I notice the merge doesn't specify a suffix. If both DataFrames have overlapping column names, Pandas will add '_x' and '_y' automatically, which could be confusing. Have we verified what columns will be in the result?"
Debugging Workflow Under Pressure

You have 60 minutes. Code breaks. Here's the fastest path to a fix.

The 5-Step Workflow

Code Breaks!
▼
STEP 1: READ
Read the error message bottom-up. 3-second read.
▼
STEP 2: LOCATE
Go to the exact line in the traceback.
▼
STEP 3: ISOLATE
Inspect with print(), .shape, .head(), .dtypes
▼
STEP 4: FIX
Fix the root cause.
Apply fix pattern from the library.
▼
STEP 5: VERIFY
Assertions, row counts, dtypes.
Code runs, data correct.

Isolation Techniques (STEP 3)

Technique Command Why It Helps
Shape print(df.shape) How many rows/cols?
First rows print(df.head(3)) What does data look like?
Dtypes print(df.dtypes) Right types?
Null count print(df.isna().sum()) How many NaN per column?
Unique values print(df['col'].unique()) What values exist?
Interview Tip: Think Out Loud
Don't debug in silence. As you isolate, narrate:

"I see the error on line 15. Let me check what the DataFrame looks like at that point. [runs df.head()] OK, I see 100 rows. Let me check the dtypes. [runs df.dtypes] The 'amount' column is object, not numeric. That's why the addition failed. Let me convert it..."

This shows confidence and helps the interviewer follow your logic.
Common Interview Traps

Interviewers will intentionally plant bugs. Here are the top traps:

Chained Indexing
▼

Assignment via chained indexing produces SettingWithCopyWarning

What They Want to Hear:

"This creates a view, not a copy. We should use .loc[] instead."

The Fix:
df.loc[df['x'] > 5, 'y'] = 10 # Unambiguous
Merge Fan-Out
▼

Duplicate keys on both sides produce Cartesian product

What They Want to Hear:

"I need to check key uniqueness before merging. Let me aggregate duplicates or use .drop_duplicates() first."

NaN in Groupby
▼

Groupby has NaN values that silently get dropped

What They Want to Hear:

"NaN values are skipped by groupby. If we need them, use .groupby('category', dropna=False) or handle explicitly."

Integer Column with NaN
▼

Assigning NaN to int column silently becomes float64

What They Want to Hear:

"Int columns can't have NaN. Either use nullable Int64, or handle NaN with .fillna() and keep as int."

inplace=True Return Value
▼

Assigning inplace=True return value results in None

What They Want to Hear:

"inplace=True returns None. Either use inplace=True without assignment, or assign the result of the regular operation."

Wrong:
df = df.drop('column', inplace=True) # df becomes None!
Missing .copy()
▼

Modifying a filtered slice without .copy()

What They Want to Hear:

"This modifies a view. We need .copy() or use .loc[]."

Wrong Merge Type
▼

Using how='inner' when you meant how='left'

What They Want to Hear:

"Inner merge only keeps matching rows. For a left join preserving all source rows, use how='left'."

axis Confusion
▼

Using axis=0 when you meant axis=1

What They Want to Hear:

"axis=0 is rows, axis=1 is columns. For clarity, use df.drop(columns=['col']) or df.drop(index=0)."

Dtype Mismatch in Merge
▼

Left key is int64, right key is float64; merge returns 0 rows

What They Want to Hear:

"Join keys must have the same dtype. Convert: df['id'] = df['id'].astype('int64') before merging."

Silent dtype Coercion
▼

Applying numeric function to string column

What They Want to Hear:

"Always check .dtypes and use pd.to_numeric() or .astype() before math operations."

Overlapping Column Names
▼

Merge without suffixes; result has _x and _y everywhere

What They Want to Hear:

"Specify suffixes=('_left', '_right') or rename columns before merging for clarity."

Pandas Version Differences
▼

Code uses .append() which was removed in Pandas 2.0

What They Want to Hear:

"Check Pandas version and use pd.concat() instead of deprecated .append()."

Strategy: When You Spot a Trap

  1. Point it out immediately: "I notice this line is using chained indexing, which might produce a warning."
  2. Explain why it's wrong: "Chained indexing creates a view, not a copy, so the assignment is ambiguous."
  3. Propose the fix: "We should use .loc[] instead."
  4. Show you'd verify: "And I'd test it to make sure the assignment actually persists."
Why Catching Traps Impresses Interviewers
Spotting and fixing a planted trap shows:
1. You've written Pandas code before
2. You think defensively about edge cases
3. You can explain the "why" behind best practices
4. You're proactive about code quality

This turns a potential mistake into a sign you're senior-level thinking.
