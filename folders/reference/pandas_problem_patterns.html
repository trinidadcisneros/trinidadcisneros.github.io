Pattern Recognition: Row-Level Filtering

What These Problems Have in Common

All filtering problems ask you to identify rows that meet certain conditions. The key is translating the business requirement into boolean indexing.

Key Signals in Problem Text

  • "Find rows where..." → Boolean mask with &, |
  • "Filter by..." → .isin(), .str.contains(), comparison operators
  • "Exclude..." → ~ (NOT) or != conditions
  • "At least / more than..." → Threshold comparisons (>=, >)

The Shared Strategy

  1. Read the condition: What rows should be included?
  2. Build the mask: Translate conditions to boolean Series
  3. Handle edge cases: NaN values, case sensitivity, string boundaries
  4. Select columns: Return only what's asked for

Common Traps

  • NaN in boolean ops: df[col] == None won't work. Use .isna() or .notna()
  • Parentheses required: df[(A) & (B)] — without parens, operator precedence breaks
  • String case: .str.contains() is case-sensitive by default; pass case=False
  • Chain vs mask: Avoid chained indexing (df[col1][col2]); use single bracket with combined mask

Pattern Recognition: GroupBy & Aggregation

What These Problems Have in Common

Aggregation problems require you to split data into groups, apply a function, and combine results. This is the split-apply-combine paradigm.

Key Signals in Problem Text

  • "Count/sum/average per..." → .groupby().agg()
  • "For each..." → .groupby() key identification
  • "Total / number of..." → .sum(), .size(), .nunique()
  • "Compare to group average..." → .transform() for row-level group stats

The Shared Strategy

  1. Identify the groups: What column(s) define each group?
  2. Choose the aggregation: sum, mean, count, nunique, min, max?
  3. Apply and shape: .agg() for multiple functions, .transform() to keep row count
  4. Post-process: Sort, filter groups (HAVING equivalent), rename columns

Common Traps

  • .count() vs .size(): count() excludes NaN; size() includes all rows
  • .nunique() vs .count(): nunique counts distinct values only
  • .transform() vs .agg(): transform returns same-length Series; agg reduces to group-level
  • Reset index: After groupby, result has group columns as index. Use .reset_index()

Pattern Recognition: Merge & Join

What These Problems Have in Common

Multi-table problems require you to combine data from two or more DataFrames using shared keys. The critical skill is choosing the right join type and key columns.

Key Signals in Problem Text

  • "Given two tables..." → pd.merge() is likely needed
  • "Find ... for each ..." across tables → Merge then groupby
  • "Regardless of whether..." → Left or outer join
  • "Self-comparison (employee vs manager)..." → Self-merge

The Shared Strategy

  1. Identify the keys: Which columns connect the tables?
  2. Choose join type: inner (both), left (keep all left rows), outer (keep all)
  3. Handle column conflicts: Use suffixes parameter for same-named columns
  4. Post-merge cleanup: Drop duplicate key columns, handle NaN from outer joins

Common Traps

  • Cartesian explosion: Duplicate keys create many-to-many joins — check with .shape
  • Key type mismatch: int vs float keys silently produce wrong results. Cast first
  • Left vs inner: Left join keeps unmatched rows as NaN — is that what you want?
  • indicator=True: Use merge indicator to check which rows matched (like SQL HAVING)

Pattern Recognition: Ranking & Top-N

What These Problems Have in Common

Ranking problems ask you to order, rank, or select the top/bottom entries based on some metric. The challenge is handling ties and group-level rankings.

Key Signals in Problem Text

  • "Find the highest/lowest..." → .idxmax(), .nlargest(), .nsmallest()
  • "Rank by..." → .rank() with appropriate method parameter
  • "Top N..." → .nlargest() or .head() after sorting
  • "Including ties..." → .rank(method='dense') or .rank(method='min')

The Shared Strategy

  1. Determine scope: Global top-N or per-group top-N?
  2. Handle ties: dense (1,1,2), min (1,1,3), or first (1,2,3)?
  3. Use right tool: .nlargest() for simple top-N; .rank() for assigned ranks
  4. Filter by rank: Compute rank column, then filter rows

Common Traps

  • Rank method matters: 'dense' doesn't skip; 'min' skips; 'first' breaks ties by position
  • .nlargest() vs .sort_values().head(): nlargest is faster for large DataFrames
  • Group-level max: .groupby().idxmax() returns index, not the row — use .loc[idx]
  • NaN in ranking: .rank() puts NaN last by default; use na_option='top' to change

Pattern Recognition: DateTime & Time Series

What These Problems Have in Common

Time series problems require date/time manipulation, period comparisons, and temporal aggregations. These often combine datetime operations with groupby and merge.

Key Signals in Problem Text

  • "Month-over-month..." → .pct_change() or .shift() after monthly groupby
  • "Rolling average..." → .rolling() on time-aggregated Series
  • "Within N days..." → pd.Timedelta or datetime subtraction
  • "Retention / returning users..." → Set operations across time periods

The Shared Strategy

  1. Parse dates: Ensure column is datetime64 with pd.to_datetime()
  2. Extract components: .dt.year, .dt.month, .dt.date, .dt.hour
  3. Group by period: .dt.to_period('M') or .dt.strftime('%Y-%m')
  4. Compare periods: .shift() for previous period, .pct_change() for growth rates

Common Traps

  • .dt accessor: Only works on datetime Series, not on DatetimeIndex — reset_index first
  • Timedelta arithmetic: Subtracting dates gives Timedelta; use .dt.days or .dt.total_seconds()
  • Period vs Timestamp: to_period('M') groups; strftime('%Y-%m') gives strings
  • Rolling requires sort: Always sort by date before applying .rolling()

Pattern Recognition: String, Reshape & Advanced Patterns

What These Problems Have in Common

Transform problems require reshaping data, string manipulation, or advanced patterns like streak detection and vote splitting.

Key Signals in Problem Text

  • "Classify / categorize based on..." → np.select() or pd.cut()
  • "Count occurrences of word..." → .str.findall() with regex
  • "Reshape / combine columns..." → pd.concat(), .explode(), .melt()
  • "Consecutive / streak..." → Cumulative sum grouping trick

The Shared Strategy

  1. Identify the transformation: Is it classification, reshaping, or pattern detection?
  2. Choose the tool: np.select for conditions, .explode() for lists, cumsum for streaks
  3. Handle edge cases: Empty strings, NaN in text, boundary conditions
  4. Verify shape: Check output dimensions match expectations

Common Traps

  • .str.contains() vs .str.findall(): contains returns bool; findall returns matches list
  • .explode() needs lists: Split strings first with .str.split()
  • Streak grouping: date - cumcount trick only works on sorted, unique dates
  • Vote splitting: Remember to handle NaN/blank voters before .groupby().transform('count')

Filtering Sub-Decisions

Simple condition df[df['col'] == value]
Problems: #37, #55, #76, #83 ▼
When to use

The problem asks you to select rows where a single column matches a specific value, threshold, or condition. Look for phrases like "find all rows where X equals Y" or "filter for status = active." This is the most common filtering pattern and should be your default starting point.

How to use

Build a boolean mask by comparing a column to a value, then pass it into bracket indexing. This is applied to the DataFrame and returns a filtered DataFrame.

# Equality df[df['status'] == 'active'] # Comparison df[df['revenue'] > 1000] # Not equal df[df['country'] != 'US']
When NOT to use

Do not use this when you have multiple conditions that must be combined with AND/OR. Do not use == None or == NaN for null checks; use .isna() or .notna() instead.

Applied to

DataFrame level. The boolean mask is created from a column (df['col'] == value returns a Series of True/False), but the indexing df[mask] filters the entire DataFrame, returning all columns for matching rows.

Multiple conditions (AND/OR) df[(cond1) & (cond2)]
Problems: #53, #93, #22 ▼
When to use

The problem requires two or more conditions combined with AND (&) or OR (|). Look for phrases like "where X and Y" or "either A or B." Common in problems that say "from 2016 with status email" or "in the US and active."

How to use

Wrap each condition in parentheses and combine with & (AND) or | (OR). Applied to the DataFrame.

# AND: both conditions must be true df[(df['year'] == 2016) & (df['status'] == 'email')] # OR: either condition df[(df['dept'] == 'Sales') | (df['dept'] == 'Marketing')] # NOT: negate a condition df[~(df['status'] == 'closed')]
When NOT to use

If you are checking membership in a list of values, use .isin() instead of chaining multiple OR conditions. Forgetting parentheses around each condition is the most common bug here due to Python's operator precedence.

Applied to

DataFrame level. Each condition produces a boolean Series from a column, and the combined mask filters the entire DataFrame.

String pattern df[df['col'].str.contains('pattern')]
Problems: #54, #35 ▼
When to use

The problem asks for partial string matching. Look for "contains," "includes," "starts with," or "ends with." Common for job title filtering ("find all Captains") or searching text fields.

How to use

Use .str.contains() for substring matches or .str.startswith() / .str.endswith() for anchored matches. Applied to a column (returns a boolean Series), then used to filter the DataFrame.

# Substring match (case insensitive, NaN safe) df[df['jobtitle'].str.contains('CAPTAIN', case=False, na=False)] # Starts with df[df['name'].str.startswith('Dr')] # Regex pattern df[df['email'].str.contains(r'@gmail\.com$', regex=True, na=False)]
When NOT to use

Do not use for exact matches; use == value instead. Always pass na=False to avoid NaN rows producing NaN in the mask, which causes indexing errors. If the pattern contains regex special characters and you want a literal match, pass regex=False.

Applied to

Column level. .str.contains() is called on a single Series and returns a boolean Series. The DataFrame is then filtered with df[mask].

Membership check df[df['col'].isin(values)]
Problems: #22, #77 ▼
When to use

The problem asks for rows matching any value from a list. Look for "find orders by Jill and Eva" or "filter for departments in [Sales, Marketing, HR]." This replaces chaining multiple OR conditions.

How to use

Pass a list (or set) of values to .isin(). Applied to a column, returns a boolean Series.

# Filter for specific names df[df['first_name'].isin(['Jill', 'Eva'])] # Exclude specific values df[~df['status'].isin(['cancelled', 'refunded'])]
When NOT to use

Do not use for a single value; == value is simpler and clearer. Do not use for partial string matching; use .str.contains() instead. .isin() performs exact matching only.

Applied to

Column level. .isin() is called on a Series and returns a boolean Series used to filter the DataFrame.

Compare to aggregate df[df['col'] > df['col'].mean()]
Problems: #81, #44 ▼
When to use

The problem asks for rows where a value exceeds (or falls below) a computed statistic of the same column. Look for "above average," "higher than median," or "greater than the max in another group."

How to use

Compute the aggregate inline and compare. The aggregate (.mean(), .median(), etc.) returns a scalar, so each row is compared against that single number. Applied to the DataFrame.

# Above average revenue df[df['revenue'] > df['revenue'].mean()] # Above median df[df['score'] >= df['score'].median()] # Compared to group-level aggregate (use transform) df[df['salary'] > df.groupby('dept')['salary'].transform('mean')]
When NOT to use

If the threshold is a fixed value (e.g., "revenue > 1000"), use a simple condition instead. If you need a group level comparison (above average within each group), use .transform() to broadcast the group aggregate back to each row.

Applied to

DataFrame level. The aggregate is computed from a column (returns a scalar), then compared row by row against the column to produce a boolean mask that filters the DataFrame.

Aggregation Sub-Decisions

Simple count/sum .groupby(key).size() or .sum()
Problems: #41, #47, #65, #73, #92 ▼
When to use

The problem asks "how many per group" or "total X per group." Look for "count of orders per customer," "total revenue by region," or "for each department, find the sum."

How to use

Group by the key column, then apply .size() (counts all rows including NaN) or [col].sum(). Applied to a grouped DataFrame, returns a Series indexed by the group key.

# Count rows per group df.groupby('department').size() # Sum a specific column df.groupby('region')['revenue'].sum() # Count non-null values in a column df.groupby('dept')['email'].count()
When NOT to use

If you need distinct counts, use .nunique() instead. .size() counts all rows (including duplicates and NaN); .count() counts non null values. If you need multiple aggregations at once, use .agg().

Applied to

Grouped DataFrame. .groupby() splits the DataFrame into groups, and the aggregation reduces each group to a single value. The result is a Series (single agg) or DataFrame (multiple columns).

Count distinct .groupby(key)[col].nunique()
Problems: #34, #50, #78 ▼
When to use

The problem asks for unique counts per group. Look for "number of distinct products per category," "unique users per month," or "how many different cities per state."

How to use

Group by the key, select the column, and call .nunique(). Applied to a grouped column.

# Unique products per category df.groupby('category')['product_id'].nunique() # Unique visitors per page df.groupby('page')['user_id'].nunique()
When NOT to use

Do not use .nunique() when you want total row counts; use .size() or .count(). .nunique() ignores NaN by default, so null values are not counted as a distinct value.

Applied to

Grouped column (Series). You must select a specific column after .groupby() before calling .nunique(). Returns a Series with the group key as the index.

Multiple agg functions .groupby(key).agg({col1: 'sum', col2: 'mean'})
Problems: #21, #71, #98 ▼
When to use

The problem asks for different aggregations on different columns in one pass. Look for "find total revenue and average rating per store" or "count orders and sum amounts by customer."

How to use

Pass a dictionary to .agg() mapping column names to aggregation functions. Applied to a grouped DataFrame, returns a DataFrame.

# Different aggs per column df.groupby('store').agg({ 'revenue': 'sum', 'rating': 'mean', 'order_id': 'count' }) # Multiple aggs on same column (use named agg) df.groupby('store').agg( total_rev=('revenue', 'sum'), avg_rev=('revenue', 'mean') )
When NOT to use

If you only need one aggregation on one column, a direct call like .sum() is simpler. The named aggregation syntax (pd.NamedAgg) is preferred over the dictionary syntax when you need custom output column names.

Applied to

Grouped DataFrame. The .agg() call operates on the grouped object and returns a DataFrame where each column has been reduced by its specified function.

Row-level group stat .groupby(key)[col].transform('mean')
Problems: #16 ▼
When to use

Define a list of boolean conditions and a matching list of labels. np.select() evaluates conditions in order and assigns the first matching label. Applied to columns, creates a new column on the DataFrame.

Column level. Each condition is a boolean Series derived from one or more columns. np.select() returns an array that you assign as a new DataFrame column.
