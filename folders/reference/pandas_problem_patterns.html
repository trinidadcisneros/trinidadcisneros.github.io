Six-Step Diagnostic Process

Run this loop top to bottom whenever you hit a new problem. It turns vague prompts into a named shape, routes you to the right branch of the Decision Tree, and gives you a failure mode to check against. Over time steps 1 to 4 collapse into seconds for patterns you recognize; slow down when a shape is unfamiliar. Each step below is collapsed by default — click to expand.

Step 1 Map the Inputs and the Output

▼

Write down what you have, what you need, and what connects them. The output shape is load bearing.

What to write down (30 seconds, before touching pandas):

  • Inputs — what tables you have, their columns, their grain (one row per what)
  • Output — what the final result should look like, including its grain
  • Connector — the transformation that bridges inputs to output

Why this step matters:

  • "One row per user with their top page" and "one row per user and page pair" land in different branches
  • The output grain determines which pattern applies, not the input
  • Skipping this step is the most common cause of picking the wrong pattern

Quick check:

  • Can you describe the output in one sentence, with the grain explicit?
  • If not, reread the prompt before moving on

Step 2 Classify the Inputs

▼

One table or many? Pick which half of the decision tree you're in.

Route by input count:

  • One table → Single-Table decision tree
  • Multiple tables → Multi-Table decision tree

Edge cases:

  • One physical table but you need to compare rows to other rows in the same table → still Multi-Table under SELF-JOIN or CHAINED SELF-JOIN
  • Aggregation that's then joined back to its source table → AGGREGATE THEN JOIN (multi-table)
  • Lookup table that's conceptually reference data → still counts as multi-table

Payoff:

  • Halves the search space before you've done any real thinking

Step 3 Name the Shape

▼

Find the verbs hiding in the prompt. Translate natural language into a named branch.

Single-Table signal words:

  • "for each", "average by", "total per", "count of X per Y" → AGGREGATE
  • "top N", "highest", "nth", "most", "least" → RANK / TOP-N
  • "only where", "with X greater than", "having", "excluding" → FILTER
  • "days between", "rolling window", "trailing N days", "since" → TIME-BASED
  • "from wide to long", "pivot", "melt", "unstack" → RESHAPE / STACK
  • "put into buckets", "classify as", "tier" → CLASSIFY / BIN

Multi-Table signal words:

  • "attach details from", "enrich with", "look up X's Y" → LOOKUP / ENRICH
  • "compare to other rows in same table", "manager of", "parent of" → SELF-JOIN
  • "multi-hop", "route through", "chain of relationships" → CHAINED SELF-JOIN
  • "is this ID in", "does this exist in", "orders that shipped" → SET MEMBERSHIP
  • "pages a friend follows but user doesn't", "items not yet owned", "gaps in coverage" → ANTI-JOIN / RECOMMENDATION
  • "match on multiple conditions", "both X and Y equal" → CROSS-JOIN / MATCH
  • "total of X per customer, joined back to customers" → AGGREGATE THEN JOIN

Rule of thumb:

  • Say the shape out loud in one sentence: "this is a <branch> because <verb>"
  • If you can't name it, you don't understand the problem yet — go back to Step 1
  • Composite patterns exist (e.g., aggregate then rank). Name both moves.

Step 4 Walk the Decision Tree by Elimination

▼

Rule out branches first, explicitly. Elimination is faster than guessing.

How to do it:

  • Start at the top of the chosen tree (Single or Multi)
  • For each candidate branch, say in one sentence why it's wrong
  • The last branch standing is your answer

Example (Recommendation System):

  • Not LOOKUP — I'm not just enriching rows with details
  • Not SELF-JOIN — the relationship crosses two tables, not one
  • Not SET MEMBERSHIP — I need a new pair list, not a filtered subset
  • Lands on ANTI-JOIN / RECOMMENDATION

Why elimination beats guessing:

  • Forces you to articulate each "no", which catches misreads of the prompt
  • Surfaces composite patterns (two branches remain → probably two steps)
  • Builds intuition faster than pattern matching from memory

If you land between two branches:

  • The problem likely needs both — plan the sequence (e.g., aggregate first, then rank)
  • Check if the output grain (from Step 1) matches the last branch in the sequence

Step 5 Grab the Recipe, Adapt from a Linked Problem

▼

Each branch has a code snippet and problem numbers. Copy; don't rederive.

On the branch card:

  • Code snippet — the canonical pandas move for that branch
  • List of linked problem numbers — click to jump to the full solution

How to adapt a linked problem:

  • Open the most similar linked problem
  • Copy the solution skeleton
  • Swap join keys and column names
  • Adjust filter conditions
  • Update output columns to match your Step 1 output spec
  • Handle edge cases (nulls, duplicates, empty groups)

Mindset:

  • Someone already paid the cost of deriving the pattern. Don't repay it.
  • Your job is to recognize the shape, not reinvent the move

Step 6 Sanity Check Against the Branch's Failure Mode

▼

Every branch has a characteristic way to go wrong. Know yours.

Failure modes by branch:

  • Merges — check .shape after each merge; watch for many to many row explosion
  • Aggregations — check grain; did each group end up with exactly one row?
  • Ranking — check tie behavior (dense, min, first, average)
  • Filters — check edge counts for off by one errors and unintended null exclusion
  • Anti joins — confirm _merge == 'left_only' is what you want; dedupe candidates before the exclusion merge
  • Datetime — verify timezone handling and whether your date range is inclusive or exclusive at both ends
  • Reshape — check that pivot didn't silently drop rows from duplicate index/column pairs
  • Classify / bin — check boundary values; is the lower or upper edge included?

Always do:

  • Run on the toy example from the prompt
  • Manually verify two or three rows of the output
  • Confirm the final .shape and grain match what you wrote down in Step 1

Red flags that mean go back to Step 4:

  • Row count ballooned unexpectedly after a merge
  • Output has the wrong grain (rows per user instead of rows per user-page pair, or vice versa)
  • A group you expected to appear isn't there (filter too aggressive? null handling?)
  • Computers are good at producing confidently wrong answers — never trust a first pass

Aggregate Per Group Into a Summary Table 20 problems

▼

This is the most common pattern in data analysis. You have granular records and need to collapse them into one row per group with an aggregated value. The prompt usually contains phrases like 'for each X, find the total/average/count of Y.'

📥 Start Condition (Input Shape)
A flat table of individual events, transactions, or records with a grouping column.
📤 End Condition (Output Shape)
One row per group with a summary statistic (count, sum, mean, nunique, etc.).
Signal words in the prompt: for each, per, by, total, average, count of, how many, number of

Template: Step-by-Step Recipe

1
Filter rows. If the problem specifies conditions (date range, category, status), apply boolean indexing first to narrow the dataset.
2
Identify the grouping key. Find the 'for each X' in the prompt. This becomes your .groupby() column(s). Multiple grouping keys go in a list: .groupby(['col1', 'col2']).
3
Choose the aggregation. Match the prompt verb to the pandas function: 'total' = .sum(), 'average' = .mean(), 'count' = .size() or .count(), 'distinct count' = .nunique().
4
Apply groupby and aggregate. df.groupby('key')['value_col'].sum(). For multiple aggregations, use .agg(name=('col','func')).
5
Post-process the output. Reset index, sort, filter to top N, or round as the problem requires.
Common failure modes: Check the grain: did you get one row per group? Check .size() for unexpected counts. If a group is missing, a filter may have been too aggressive or NaN excluded a row.

Rank or Find Top-N Within Groups 15 problems

▼

You need to order rows by a value and either assign ranks, extract the top N, or find the row with the highest or lowest value per group. The key decision is how to handle ties.

📥 Start Condition (Input Shape)
A table with a numeric or ordinal column and optionally a grouping column.
📤 End Condition (Output Shape)
Ranked rows, top-N per group, or the single best/worst row per group.
Signal words in the prompt: top N, highest, lowest, rank, most, least, best, worst, nth, second highest

Template: Step-by-Step Recipe

1
Filter and aggregate first if needed. If the problem says 'top 5 by total sales', you need to groupby and sum first, THEN rank the result.
2
Choose your ranking tool. .rank(method='dense') for ties sharing rank with no gaps. .rank(method='first') for unique ranks. .nlargest()/.nsmallest() for quick top-N. .idxmax()/.idxmin() for the single best row.
3
For global top-N. df.nlargest(N, 'col') or df.sort_values('col', ascending=False).head(N).
4
For per-group top-N. .groupby('group')['value'].rank(method='dense', ascending=False), then filter to rank <= N.
5
Handle ties explicitly. The prompt usually specifies: 'include ties' = dense rank; 'unique ranks' = method='first' with a tiebreaker sort.
Common failure modes: Wrong rank method (dense vs min vs first). Forgetting to aggregate before ranking (ranking raw rows instead of group totals). Off-by-one on rank cutoff (rank <= 5 vs rank < 5).

📥 Start Condition (Input Shape)

Hard #101. The Cheapest Airline Connection

▼

Find the cheapest trip between every origin and destination pair, allowing up to two stops. A single flights table contains origin, destination, and cost columns.

Tables: da.flights (id, origin, destination, cost)

→

Key Pandas Concepts

Chained self-merge (df.merge(df) up to 3 legs), pd.concat() to stack route options, .groupby().min() for cheapest per pair

Decision Tree Path

START → ONE TABLE → but it requires SELF-JOIN (Multi-Table tree) → CHAINED SELF-JOIN because you need to build multi-hop routes by merging the flights table with itself 2 and 3 times, then combine all route lengths with pd.concat() and take the min cost per pair.

Strategy Breakdown

  1. Direct flights (0 stops): just the raw table as is
  2. One stop flights (2 legs): self-merge where leg1.destination == leg2.origin, sum costs, filter out circular trips
  3. Two stop flights (3 legs): chain a third self-merge, sum all three costs, filter out any leg that loops back
  4. Combine: pd.concat() all three DataFrames
  5. Find cheapest: .groupby(['origin', 'destination'])['cost'].min()
▶ Solution Pandas Approach
# Direct flights (0 stops) direct = da.flights[['origin', 'destination', 'cost']].copy() # 1-stop flights (2 legs) one_stop = ( da.flights.merge(da.flights, left_on='destination', right_on='origin', suffixes=('_1', '_2')) .query('origin_1 != destination_2') .assign(origin=lambda x: x['origin_1'], destination=lambda x: x['destination_2'], cost=lambda x: x['cost_1'] + x['cost_2']) [['origin', 'destination', 'cost']] ) # 2-stop flights (3 legs) two_stop = ( da.flights.merge(da.flights, left_on='destination', right_on='origin', suffixes=('_1', '_2')) .merge(da.flights, left_on='destination_2', right_on='origin') .query('origin_1 != destination_2 and origin_1 != destination and origin_2 != destination') .assign(origin=lambda x: x['origin_1'], destination_final=lambda x: x['destination'], cost=lambda x: x['cost_1'] + x['cost_2'] + x['cost']) .rename(columns={'destination_final': 'destination'}) [['origin', 'destination', 'cost']] ) # Combine all routes and find cheapest per pair result = ( pd.concat([direct, one_stop, two_stop]) .groupby(['origin', 'destination'], as_index=False)['cost'] .min() .rename(columns={'cost': 'min_price'}) .sort_values(['origin', 'destination']) .reset_index(drop=True) )
