SELECT & FROM: Retrieving Data

The SELECT statement is the foundation of SQL. It retrieves data from tables in your database. Here are the core patterns you need to know.

SELECT * — Retrieve All Columns

Use SELECT * to get all columns from a table. This is useful for exploration but avoid it in production code when you only need specific columns.

SELECT * FROM table_name;

Example:

SELECT * FROM hiv_prev_subset LIMIT 5;

SELECT Specific Columns

When you know which columns you need, specify them explicitly. This improves performance and clarity.

SELECT column1, column2, column3 FROM table_name;

Example — Single Column:

SELECT Belize FROM hiv_prev_subset;

Example — Multiple Columns:

SELECT Belize, Australia, Burundi FROM hiv_prev_subset;

Tip: Always list specific columns. Avoid SELECT * in production queries. It's less efficient, harder to maintain, and can break if the table structure changes.

DISTINCT — Remove Duplicate Rows

Use DISTINCT to see unique values in a column. This is helpful for data exploration and understanding what values exist.

SELECT DISTINCT column_name FROM table_name;

Example:

SELECT DISTINCT Belize FROM hiv_prev_subset;

This returns only the unique HIV prevalence values for Belize, removing duplicates from the result set.

LIMIT — Control Row Count

Use LIMIT to restrict the number of rows returned. This is essential for exploring large tables without downloading millions of rows.

SELECT * FROM table_name LIMIT 5;

Example:

SELECT * FROM hiv_prev_subset LIMIT 5;

With OFFSET (for pagination):

SELECT * FROM table_name LIMIT 5 OFFSET 10;

This skips the first 10 rows and returns the next 5 rows.

Table Aliases

Use aliases to shorten table names and make code more readable, especially when working with multiple tables.

SELECT t.column1, t.column2 FROM table_name AS t;

Comments in SQL

Add comments to explain your queries. Use -- for single-line comments or /* */ for multi-line comments.

-- This is a single-line comment SELECT * FROM table_name; -- Gets all data /* This is a multi-line comment that spans multiple lines */ SELECT column1 FROM table_name;

Filtering: WHERE Clause & Operators

Filtering narrows your results to only the rows you need. Master WHERE and its operators to extract exactly what you're looking for.

WHERE — Basic Filtering

The WHERE clause filters rows based on conditions. It comes after FROM but before ORDER BY.

SELECT column(s) FROM table_name WHERE column = SOMEVALUE;

Example:

SELECT LocationDesc, HealthTopic, PolicyTopic, Setting FROM cdc_npaol_data WHERE LocationAbbr = 'CA';

Key Point: You can filter on columns that are not in the SELECT list. Just make sure they exist in the same table.

Comparison Operators

Operator Meaning Example
= Equal to WHERE age = 30
<> or != Not equal to WHERE city <> 'NYC'
< Less than WHERE price < 100
<= Less than or equal WHERE date <= '2023-12-31'
> Greater than WHERE score > 85
>= Greater than or equal WHERE rating >= 4.0

Example with numeric operator:

SELECT * FROM cdc_npaol_data WHERE StatusAltValue < 3 ORDER BY LocationDesc;

Example with NOT EQUAL:

SELECT * FROM cdc_npaol_data WHERE LocationDesc <> 'Arkansas';

NULL Checks

NULL represents missing data. Use IS NULL and IS NOT NULL to find or exclude rows with missing values.

-- Find rows with NULL values SELECT * FROM table_name WHERE column IS NULL; -- Find rows without NULL values SELECT * FROM table_name WHERE column IS NOT NULL;

Important: = NULL does NOT work in SQL. Always use IS NULL or IS NOT NULL.

LIKE — Pattern Matching with Wildcards

Use LIKE with wildcards (% and _) to search for text patterns. The % matches any number of characters; _ matches a single character.

-- Starts with pattern SELECT * FROM table_name WHERE column LIKE 'pattern%'; -- Contains pattern SELECT * FROM table_name WHERE column LIKE '%pattern%'; -- Ends with pattern SELECT * FROM table_name WHERE column LIKE '%pattern';

Example — Starts with "Cocaine":

SELECT * FROM accidentaldrugdeaths WHERE COD LIKE 'Cocaine%' LIMIT 5;

Example — Contains "hydrocod":

SELECT * FROM accidentaldrugdeaths WHERE COD LIKE '%hydrocod%' LIMIT 5;

Underscore Wildcard (_ matches one character):

SELECT * FROM accidentaldrugdeaths WHERE Sex LIKE 'F_male' LIMIT 5;

AND — Multiple Conditions (All Must Be True)

Use AND when you need rows that satisfy multiple conditions. All conditions must be TRUE.

SELECT column(s) FROM table_name WHERE condition1 AND condition2;

Example:

SELECT * FROM accidentaldrugdeaths WHERE Sex = 'Male' AND Age > 20 ORDER BY Age DESC;

OR — Multiple Conditions (Any Can Be True)

Use OR when any one condition can be TRUE. The row is included if at least one condition matches.

SELECT column(s) FROM table_name WHERE condition1 OR condition2;

Example:

SELECT * FROM accidentaldrugdeaths WHERE Age > 20 OR Race <> 'White' ORDER BY Age;

IN — Specify Multiple Values

Use IN instead of multiple OR conditions. More readable when you're checking if a value is in a list.

SELECT column(s) FROM table_name WHERE column IN (value1, value2, value3);

Example — Find records from specific states:

SELECT * FROM cdc_npaol_data WHERE LocationDesc IN ('California', 'Texas', 'New York');

NOT — Negate a Condition

Use NOT to negate a condition. It inverts the logic.

SELECT column(s) FROM table_name WHERE NOT column = SOMEVALUE;

Example:

SELECT * FROM accidentaldrugdeaths WHERE NOT Sex = 'Male';

NOT IN — Exclude values from a list:

SELECT * FROM cdc_npaol_data WHERE LocationDesc NOT IN ('Arkansas', 'Oklahoma');

BETWEEN — Specify a Range

Use BETWEEN for numeric or date ranges. It's inclusive (includes both boundaries).

SELECT column(s) FROM table_name WHERE column BETWEEN value1 AND value2;

Example:

SELECT * FROM cdc_npaol_data WHERE Year BETWEEN 2009 AND 2011 ORDER BY Year;

Parentheses for Clarity

Use parentheses to explicitly control the order of operations when combining AND/OR.

SELECT column(s) FROM table_name WHERE (columnA = SOMEVALUE OR columnB = SOMEVALUE) AND columnC = SOMEVALUE;

Example:

SELECT * FROM accidentaldrugdeaths WHERE (Age > 20 AND Race = 'White') OR DeathCity = 'Bristol' ORDER BY Age;

Tip: Parentheses make complex WHERE clauses easier to read and understand. Use them liberally!

Sorting & Calculated Fields

ORDER BY sorts results, while calculated fields let you create new columns from existing data using expressions and functions.

ORDER BY — Sort Results

Use ORDER BY to sort the result set. Place it after WHERE but at the very end of the query.

-- Ascending (default) SELECT column(s) FROM table_name ORDER BY column; -- Descending SELECT column(s) FROM table_name ORDER BY column DESC;

Example — Alphabetic Ascending:

SELECT Year, LocationDesc, PolicyTopic FROM cdc_npaol_data ORDER BY LocationDesc;

Example — Numeric Descending:

SELECT Year, LocationDesc, PolicyTopic FROM cdc_npaol_data ORDER BY Year DESC;

ORDER BY Multiple Columns

Sort by multiple columns. The first column is the primary sort; subsequent columns break ties.

SELECT Year, Quarter, LocationAbbr, HealthTopic FROM cdc_npaol_data ORDER BY Year DESC, HealthTopic ASC;

This sorts by Year (newest first), then by HealthTopic (A to Z) within each year.

ORDER BY Column Position

Instead of column names, you can reference columns by their position in the SELECT list (1-indexed).

-- Column 1 DESC, Column 3 ASC, Column 5 default (ASC) SELECT Year, Quarter, LocationAbbr, LocationDesc, HealthTopic FROM cdc_npaol_data ORDER BY 1 DESC, 3 ASC, 5;

Warning: Column position references are fragile. If you add or reorder columns in SELECT, the ORDER BY breaks. Use column names instead for production code.

CONCAT — Join Text Columns

Use CONCAT() to combine values from multiple columns into one. The syntax varies by database.

-- MySQL / MariaDB SELECT CONCAT(column1, ' ', column2) AS full_column FROM table_name; -- PostgreSQL / SQLite / Oracle / DB2 SELECT column1 || ' ' || column2 AS full_column FROM table_name;

Example:

SELECT CONCAT(track_name, '. App Category: ', prime_genre) FROM apple_apps LIMIT 5;

Aliases with AS

Use AS to rename columns in output. Aliases make results more readable and are essential for calculated fields.

SELECT CONCAT(track_name, '. App Category: ', prime_genre) AS Concatenated_Column FROM apple_apps LIMIT 5;

Alias without AS (works in most databases):

SELECT column1 old_name FROM table_name;

Mathematical Operations

Create calculated fields using +, -, *, and / operators on numeric columns.

Operator Operation
+ Addition
- Subtraction
* Multiplication
/ Division

Example — Calculate revenue:

SELECT track_name, (rating_count_tot * price) AS revenue FROM apple_apps LIMIT 5;

Example — Combine math and concatenation:

SELECT track_name, CONCAT('$', (rating_count_tot * price)) AS revenue FROM apple_apps LIMIT 5;

CASE Expressions for Conditional Logic

Use CASE to assign values based on conditions. It's like an if-then-else statement.

SELECT column_name, CASE WHEN condition1 THEN value1 WHEN condition2 THEN value2 ELSE default_value END AS new_column FROM table_name;

Example:

SELECT track_name, price, CASE WHEN price = 0 THEN 'Free' WHEN price < 5 THEN 'Cheap' WHEN price < 20 THEN 'Moderate' ELSE 'Expensive' END AS price_category FROM apple_apps;

SQL Functions: Transform Your Data

Functions manipulate data values. Master text, numeric, and date functions to transform raw data into useful information.

Text Functions

Text functions extract, modify, and analyze string values.

Function Purpose Example
UPPER() Convert to uppercase UPPER('hello') → 'HELLO'
LOWER() Convert to lowercase LOWER('Hello') → 'hello'
LENGTH() Count characters LENGTH('SQL') → 3
LEFT() Extract leftmost N characters LEFT('Apple', 3) → 'App'
RIGHT() Extract rightmost N characters RIGHT('Apple', 3) → 'ple'
SUBSTRING() / SUBSTR() Extract substring SUBSTRING('Apple', 2, 3) → 'ppl'
TRIM() Remove leading/trailing spaces TRIM(' hello ') → 'hello'
REPLACE() Replace text REPLACE('hello', 'l', 'x') → 'hexxo'

Example — Extract leftmost 5 characters:

SELECT Security, LEFT(Security, 5) AS Left_Trimmed FROM portfolio LIMIT 5;

Example — Get string length:

SELECT Security, LENGTH(Security) AS Length FROM portfolio LIMIT 5;

Example — Uppercase conversion:

SELECT Security, UPPER(Security) AS UpperCased FROM portfolio LIMIT 5;

Numeric Functions

Numeric functions perform mathematical operations and transformations.

Function Purpose Example
ROUND() Round to N decimal places ROUND(3.14159, 2) → 3.14
CEIL() / CEILING() Round up to nearest integer CEIL(3.2) → 4
FLOOR() Round down to nearest integer FLOOR(3.8) → 3
ABS() Absolute value ABS(-5) → 5
MOD() Modulo (remainder) MOD(10, 3) → 1
SQRT() Square root SQRT(9) → 3

Example — Average of a column:

SELECT AVG(mean_return) AS Average FROM portfolio;

Example — Find maximum value with grouping:

SELECT MyUnknownColumn, MAX(mean_return) AS MaxReturn FROM portfolio GROUP BY MyUnknownColumn ORDER BY MaxReturn DESC LIMIT 5;

Date Functions: Extract Components

Date functions break dates into components or perform date arithmetic.

Function Purpose Example
YEAR() Extract year YEAR('2020-08-06') → 2020
MONTH() Extract month (1-12) MONTH('2020-08-06') → 8
DAY() Extract day (1-31) DAY('2020-08-06') → 6
DAYNAME() Day of week name DAYNAME('2020-08-06') → 'Thursday'
DAYOFWEEK() Day number (1=Sunday) DAYOFWEEK('2020-08-06') → 5
DAYOFYEAR() Day of year (1-366) DAYOFYEAR('2020-08-06') → 219

Example — Extract year, month, day:

SELECT Date, YEAR(Date) AS Year_method, MONTH(Date) AS Month_method, DAY(Date) AS Day_method FROM calendartable LIMIT 5;

Example — Extract multiple date components:

SELECT Date, DAYNAME(Date) AS TheDayName, DAYOFWEEK(Date) AS TheDayOfWeek, DAYOFMONTH(Date) AS TheDayOfMonth, DAYOFYEAR(Date) AS TheDayOfYear FROM calendartable LIMIT 5;

Date Functions: EXTRACT()

PostgreSQL and MySQL support EXTRACT() for accessing date components with temporal intervals.

SELECT Date, EXTRACT(YEAR FROM Date) AS Year, EXTRACT(YEAR_MONTH FROM Date) AS YearMonth, EXTRACT(DAY FROM Date) AS Day, EXTRACT(QUARTER FROM Date) AS Quarter FROM calendartable LIMIT 5;

Date Functions: DATE_FORMAT()

Format and extract date parts using DATE_FORMAT(). Available in MySQL.

SELECT Date, DATE_FORMAT(Date, '%W') AS TheDayName, DATE_FORMAT(Date, '%M') AS TheMonth, DATE_FORMAT(Date, '%u') AS TheWeekOfYear FROM calendartable LIMIT 5;

Aggregate Functions

These functions compute a single value from a set of values (typically used with GROUP BY).

Function Purpose Example
COUNT() Count rows COUNT(*) → 1000
SUM() Sum values SUM(amount) → 5000
AVG() Average values AVG(price) → 49.99
MIN() Minimum value MIN(rating) → 1.5
MAX() Maximum value MAX(age) → 95

Example — Count rows:

SELECT COUNT(mean_return) AS Total_Count FROM portfolio;

Type Conversion Functions

Convert between data types when needed.

Function Purpose
CAST(value AS type) Convert value to type (works in all databases)
COALESCE(value1, value2, ...) Return first non-NULL value
NULLIF(expr1, expr2) Return NULL if expressions equal

Example:

SELECT CAST('2020-08-06' AS DATE) AS converted_date; SELECT COALESCE(middle_name, 'N/A') AS middle FROM customers;

GROUP BY & Aggregation

GROUP BY organizes data into categories, while aggregate functions compute summaries per group. This is how you create reports and perform analysis.

GROUP BY — Organize Data into Groups

GROUP BY divides rows into logical groups and applies aggregate functions to each group.

SELECT column, aggregate_function(column) AS alias FROM table_name GROUP BY column;

Example — Count stocks by sector:

SELECT `GICS Sector`, COUNT(MyUnknownColumn) AS Total_Stocks FROM portfolio GROUP BY `GICS Sector`;

This returns:

Health Care 59 Industrials 69 Consumer Discretionary 84 Information Technology 68 Consumer Staples 36 ... (and more)

GROUP BY Rules

Follow these essential rules when using GROUP BY:

  1. Every non-aggregated column in SELECT must appear in GROUP BY
  2. Aggregate functions (COUNT, SUM, AVG, etc.) can be used without GROUP BY
  3. GROUP BY can contain multiple columns for nested grouping
  4. NULL values are treated as a separate group
  5. GROUP BY comes after WHERE and before HAVING

COUNT() Function Behavior

Expression Behavior
COUNT(*) Counts all rows, including NULLs
COUNT(column) Counts non-NULL values in column
COUNT(DISTINCT column) Counts unique non-NULL values

HAVING — Filter Groups (Not Rows)

Use HAVING to filter groups by their aggregated values. WHERE filters rows; HAVING filters groups.

SELECT column, aggregate_function(column) AS alias FROM table_name GROUP BY column HAVING aggregate_condition;

Example — Filter sector by count:

SELECT `GICS Sector`, COUNT(MyUnknownColumn) AS Total_Stocks FROM portfolio GROUP BY `GICS Sector` HAVING COUNT(MyUnknownColumn) > 20;

Returns only sectors with more than 20 stocks.

Example — Filter by multiple conditions:

SELECT `GICS Sector`, COUNT(MyUnknownColumn) AS Total_Stocks FROM portfolio GROUP BY `GICS Sector` HAVING COUNT(MyUnknownColumn) > 20 AND COUNT(MyUnknownColumn) <= 40;

WHERE vs. HAVING

WHERE HAVING
Filters rows BEFORE grouping Filters groups AFTER grouping
Works with any column Works with aggregates
Reduces data before processing Reduces groups after processing

Example — Combining WHERE and HAVING:

SELECT `GICS Sector`, COUNT(MyUnknownColumn) AS Total_Stocks FROM portfolio WHERE mean_return >= 0.3 GROUP BY `GICS Sector` HAVING COUNT(MyUnknownColumn) > 2;

This first filters stocks with mean_return >= 0.3, then groups by sector and only returns sectors with more than 2 qualifying stocks.

GROUP BY Multiple Columns

Group by multiple columns to create nested groups and cross-tabulations.

SELECT column1, column2, COUNT(*) AS total FROM table_name GROUP BY column1, column2;

Query Clause Ordering

The order of clauses matters. This is the correct sequence:

Clause Purpose Required?
SELECT Specify columns to retrieve Yes
FROM Specify table(s) Yes
WHERE Filter rows (before grouping) No
GROUP BY Organize rows into groups No
HAVING Filter groups (after grouping) No
ORDER BY Sort final results No

Complete example with all clauses:

SELECT Year, LocationDesc, COUNT(*) AS policy_count FROM cdc_npaol_data WHERE Year >= 2010 GROUP BY Year, LocationDesc HAVING COUNT(*) > 5 ORDER BY Year DESC, policy_count DESC;

GROUP BY vs. ORDER BY

GROUP BY ORDER BY
Returns organized groups Organizes returned data
Required with aggregates Optional
Uses only selected columns Can use any column (even hidden ones)

SQL Dialects: Choosing the Right Database

SQL is a standard language, but each database vendor has added its own extensions and variations called dialects. Understanding the differences helps you write portable and efficient code.

Why SQL Dialects Exist

In the 1970s-1980s, many vendors developed their own versions of SQL before standards were established. By the time ANSI/ISO SQL standards were created (1986-1987), many vendor-specific features already existed. Rather than discard innovations, vendors maintained compatibility while adding proprietary features.

This means:

  • Core SQL (SELECT, WHERE, GROUP BY, etc.) works on all databases
  • Advanced features (window functions, CTEs, JSON) vary by vendor
  • Syntax for the same operation differs across databases
  • Some functions have different names or behavior

Major SQL Dialects

Database Vendor Cost Common Use Cases
MySQL / MariaDB Oracle / MariaDB Foundation Free & Open Source Web applications, content management systems (WordPress, Drupal), high-traffic sites
PostgreSQL PostgreSQL Global Development Group Free & Open Source Advanced applications, JSON support, PostGIS for geospatial, analytics
SQLite D Richard Hipp Free & Open Source Mobile apps, embedded databases, single-file databases, lightweight projects
SQL Server Microsoft Commercial Enterprise applications, Windows environments, data warehousing, SSRS reporting
Oracle Database Oracle Corporation Commercial Large enterprises, mission-critical applications, complex transactions, OLTP
DB2 IBM Commercial Enterprise data management, mainframe integration, NoSQL support

Key Syntax Differences

Here are common operations that differ across dialects:

String Concatenation
+
-- MySQL SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM users; -- PostgreSQL, Oracle, SQLite, DB2 SELECT first_name || ' ' || last_name AS full_name FROM users; -- SQL Server SELECT first_name + ' ' + last_name AS full_name FROM users;
Extract Year from Date
+
-- MySQL, PostgreSQL, DB2 SELECT YEAR(order_date) AS year FROM orders; -- Oracle, SQL Server SELECT EXTRACT(YEAR FROM order_date) AS year FROM orders; -- SQLite SELECT strftime('%Y', order_date) AS year FROM orders;
Case Sensitivity in Comparisons
+
-- MySQL is NOT case-sensitive by default SELECT * FROM users WHERE name = 'john'; -- matches 'John', 'JOHN', 'john' -- PostgreSQL IS case-sensitive by default SELECT * FROM users WHERE name = 'john'; -- matches only 'john' SELECT * FROM users WHERE LOWER(name) = 'john'; -- matches any case -- SQL Server is NOT case-sensitive by default -- SQLite is NOT case-sensitive by default
Extract Substring
+
-- MySQL SELECT SUBSTRING(email, 1, 5) AS first_five FROM users; -- PostgreSQL, SQLite SELECT SUBSTR(email, 1, 5) AS first_five FROM users; -- Oracle, DB2 SELECT SUBSTR(email, 1, 5) AS first_five FROM users; -- SQL Server SELECT SUBSTRING(email, 1, 5) AS first_five FROM users;
Get Current Date/Time
+
-- MySQL, MariaDB SELECT CURDATE() AS today, CURTIME() AS now; SELECT NOW() AS current_timestamp; -- PostgreSQL SELECT CURRENT_DATE, CURRENT_TIME; SELECT NOW() AS current_timestamp; -- SQLite SELECT DATE('now') AS today; SELECT DATETIME('now') AS current_timestamp; -- SQL Server SELECT CAST(GETDATE() AS DATE) AS today; SELECT GETDATE() AS current_timestamp; -- Oracle SELECT TRUNC(SYSDATE) AS today; SELECT SYSDATE AS current_timestamp;
Limit Result Rows
+
-- MySQL, PostgreSQL, SQLite, MariaDB SELECT * FROM users LIMIT 10; -- SQL Server SELECT TOP 10 * FROM users; -- Oracle SELECT * FROM users WHERE ROWNUM <= 10; -- Or (Oracle 12c+) SELECT * FROM users FETCH FIRST 10 ROWS ONLY; -- DB2 SELECT * FROM users FETCH FIRST 10 ROWS ONLY;
Comments in SQL
+
-- Single-line comments (all databases) SELECT * FROM users; -- Gets all users /* Multi-line comments (all databases) */ SELECT * FROM users; /* SQL Server specific */ -- Supports T-SQL comment syntax -- PRINT 'Server: ' + @@SERVERNAME;

Choosing a Database for Your Project

Choose MySQL/MariaDB if:

  • You're building a web application
  • You need a simple, fast database
  • Open source is important to you
  • Cost is a factor (it's free)

Choose PostgreSQL if:

  • You need advanced SQL features
  • You work with JSON data
  • You need ACID compliance and reliability
  • You prefer open source

Choose SQLite if:

  • You're building a mobile app
  • You need a simple embedded database
  • You don't need a client-server setup
  • You want zero administration

Choose SQL Server if:

  • You're in a Microsoft/.NET environment
  • You need advanced reporting (SSRS)
  • You're building an enterprise application
  • Integration with Office/SharePoint is needed

Choose Oracle if:

  • You have mission-critical applications
  • You need extreme scalability
  • You're in a large enterprise
  • Cost is not a primary concern

Writing Portable SQL

When writing code that needs to work across databases, follow these best practices:

  1. Stick to standard SQL — Use features defined by ANSI/ISO standard
  2. Use CAST() for type conversion — Works everywhere
  3. Avoid vendor-specific functions when possible
  4. Be explicit with date formats — Different databases handle dates differently
  5. Test on all target databases — Syntax that works in MySQL may fail in PostgreSQL
  6. Document any vendor-specific code — Make it clear when you're using non-standard syntax

Pro Tip: Use an abstraction layer like SQLAlchemy (Python), Sequelize (Node.js), or Hibernate (Java). These ORMs handle dialect differences for you.
