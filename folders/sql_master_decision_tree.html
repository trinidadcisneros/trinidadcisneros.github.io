Instead of choosing between three separate strategy guides, start here — the tree will route you to the correct technique and tell you which guide to dig into for details. How to use this guide: Read the problem statement, then walk down the tree answering each question. You'll land on the right pattern in under 30 seconds.

Step 1: How Many Tables?

This is always the first question. Everything else follows from it.

READ THE PROBLEM STATEMENT

1. How many tables are mentioned?
2. What does the expected output look like?
3. Are there aggregation words (total, average, %)?
4. Are there NULL / string / date clues?

▼
ONE TABLE
Go to Step 2A: Single-Table Path →
TWO OR MORE TABLES

> Watch out — "one table" can be tricky. A table that references itself (e.g., manager_id pointing to the same Employees table) is a Self JOIN problem. If the problem says "compare to previous row" and there's only one table, you still go to Step 2A — use LAG/LEAD, not a self-join.

Step 2A: Single-Table Path

You only have one table. Walk through these questions in order — the first YES is your answer.

> NULL trap: If filtering involves != value, remember that NULL != value is NULL (not TRUE). Add OR col IS NULL to include NULLs. Example: "Find customers NOT referred by id 2" needs WHERE refereeid != 2 OR refereeid IS NULL.

SINGLE TABLE — What am I doing?
▼
Just filtering rows by conditions on columns?
(both, either/or, not equal, greater than, odd/even)
YES → singletablequerystrategies.html">WHERE + ORDER BYSELECT cols FROM table WHERE condition1 AND condition2 ORDER BY col Watch for NULLs — col != X does NOT include NULLs
if no ▼
Does it involve string / text manipulation?
(fix names, pattern match, valid emails, length, contains prefix)
YES → singletablequerystrategies.html">String functions-- Pattern matching: WHERE col LIKE 'DIAB1%' OR col LIKE '% DIAB1%' -- Regex (Postgres): WHERE col ~ '^[A-Za-z][A-Za-z0-9._-]*@domain\\.com$' -- Fix capitalization: CONCAT(UPPER(LEFT(name,1)), LOWER(SUBSTRING(name,2))) -- Filter by length: WHERE LENGTH(content) > 15
if no ▼
Does it involve dates?
(per month, yesterday, past 30 days, first order date)
YES → See DATE FORK (Step 3) → then come back here for the structural pattern
if no ▼
Am I comparing rows to each other?
(previous, next, consecutive, yesterday vs today, swap adjacent)
YES → singletablequerystrategies.html">LAG() / LEAD() — window functionsSELECT *, LAG(col) OVER(ORDER BY datecol) AS prevval, LEAD(col) OVER(ORDER BY datecol) AS nextval FROM table For "3+ consecutive same value" → check LAG(col,1) AND LAG(col,2)
if no ▼
Am I collapsing rows into a summary?
(count, sum, average, number of distinct, total per group)
YES → singletablequerystrategies.html">GROUP BY + aggregate functionSELECT group_col, COUNT(*), SUM(val), AVG(val), COUNT(DISTINCT other_col) FROM table GROUP BY group_col STRING_AGG(col, ',') to concatenate values per group
if no ▼
Filtering AFTER grouping?
("at least 5 students", "appeared only once", "groups where count > N")
YES → singletablequerystrategies.html">GROUP BY + HAVINGSELECT group_col, COUNT(*) FROM table GROUP BY group_col HAVING COUNT(*) >= 5 "Biggest single number" → HAVING COUNT = 1, then MAX
if no ▼
Computing a rate, ratio, or conditional metric?
(confirmation rate, % approved, poor query %, immediate %)
YES → singletablequerystrategies.html">Conditional aggregation — CASE inside SUM or AVGSELECT group_col, ROUND(AVG(CASE WHEN state = 'approved' THEN 1.0 ELSE 0 END) * 100, 2) AS approved_pct, SUM(CASE WHEN state = 'approved' THEN amount ELSE 0 END) AS approved_total FROM table GROUP BY group_col
if no ▼
Am I ranking rows?
("top N per group", "second highest", "nth largest", "top three salaries")
YES → singletablequerystrategies.html">ROWNUMBER() / RANK() / DENSERANK()SELECT * FROM ( SELECT *, DENSE_RANK() OVER(PARTITION BY group_col ORDER BY val DESC) AS rn FROM table ) sub WHERE rn <= 3 ROWNUMBER = unique ranks; DENSERANK = ties share rank
if no ▼
Running total, cumulative sum, or rolling window?
(running sum, moving average, 7-day window, last person under limit)
YES → singletablequerystrategies.html">SUM() / AVG() OVER() — window function-- Running total: SUM(amount) OVER(ORDER BY turn) AS running_total -- 7-day rolling average (pre-aggregate first): AVG(daily_total) OVER( ORDER BY visit_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW ) AS rolling7avg
if no ▼
Labeling / categorizing / swapping?
("if X then Y", "triangle judgement", "swap seats", salary categories)
YES → singletablequerystrategies.html">CASE WHENSELECT *, CASE WHEN x + y > z AND x + z > y AND y + z > x THEN 'Yes' ELSE 'No' END AS triangle FROM table For "must include all categories even with zero count" → generate categories with VALUES or UNION, then LEFT JOIN
if no ▼
Pivoting rows → columns?
YES → singletablequerystrategies.html">CASE + GROUP BY (pivot)SELECT group_col, SUM(CASE WHEN category = 'A' THEN val ELSE 0 END) AS A, SUM(CASE WHEN category = 'B' THEN val ELSE 0 END) AS B FROM table GROUP BY group_col
if no ▼
Finding missing data or "NOT IN" another set?
YES → NOT EXISTS / NOT IN / IS NULLSELECT * FROM table t1 WHERE NOT EXISTS ( SELECT 1 FROM table t2 WHERE t2.id = t1.related_id )
if no ▼
Removing or identifying duplicates?
YES → ROW_NUMBER() to deduplicate-- Keep one row per key: SELECT * FROM ( SELECT *, ROW_NUMBER() OVER(PARTITION BY key_col ORDER BY id ASC) AS rn FROM table ) sub WHERE rn = 1
if no ▼
DELETE statement required?
(delete duplicates, keep smallest id)
YES → DELETE with self-referenceDELETE FROM Person p1 USING Person p2 WHERE p1.email = p2.email AND p1.id > p2.id

Two or more tables. Walk through these questions in order — the first YES is your JOIN type.

MULTIPLE TABLES — How do they relate?
▼
Two separate questions combined into one result?
(e.g., "user who rated most movies" AND "movie with highest avg rating")
YES → multitablequerystrategies.html">UNION ALL (separate queries)
Write each query independently, stack with UNION ALL(SELECT name AS results FROM ... ORDER BY ... LIMIT 1) UNION ALL (SELECT title AS results FROM ... ORDER BY ... LIMIT 1)
if no ▼
Same structure / similar data to combine?
("combine", "merge", "both requesters and accepters")
YES → multitablequerystrategies.html">UNION ALL (or UNION)
Stack rows from both sourcesSELECT requester_id AS id FROM RequestAccepted UNION ALL SELECT accepter_id AS id FROM RequestAccepted UNION ALL keeps dupes (faster); UNION removes them
if no ▼
Table references itself?
("manager", "parent", "reports to", "same table twice")
YES → multitablequerystrategies.html">Self JOINSELECT a.name AS employee, b.name AS manager FROM employees a JOIN employees b ON a.manager_id = b.id "Manager left" = LEFT JOIN self, WHERE manager IS NULL
if no ▼
Need ALL combinations?
("every student with every subject", generate all pairs)
YES → multitablequerystrategies.html">CROSS JOINSELECT s.studentname, sub.subjectname FROM Students s CROSS JOIN Subjects sub Often followed by LEFT JOIN to count actuals vs all possibilities
if no ▼
Need to find what's MISSING?
("never", "didn't", "no match", "visited but no transaction")
YES → multitablequerystrategies.html">LEFT JOIN + WHERE IS NULL
(anti-join pattern)SELECT a.* FROM customers a LEFT JOIN orders b ON a.id = b.customer_id WHERE b.customer_id IS NULL
if no ▼
Joining on a date range or non-equality condition?
("price valid between start and end date", "within N days")
YES → multitablequerystrategies.html">Range JOIN (non-equi)SELECT a.*, b.price FROM UnitsSold a JOIN Prices b ON a.productid = b.productid AND a.purchase_date BETWEEN b.startdate AND b.enddate
if no ▼
"Bought ALL products" / must match every item in a set?
("customers who bought all products", relational division)
YES → multitablequerystrategies.html">GROUP BY + HAVING COUNT(DISTINCT) = subquerySELECT customer_id FROM Customer GROUP BY customer_id HAVING COUNT(DISTINCT product_key) = (SELECT COUNT(*) FROM Product)
if no ▼
Must keep ALL rows from one table even if no match?
("show null if no match", "include users with zero orders")
YES → multitablequerystrategies.html">LEFT JOINSELECT a.*, COALESCE(b.val, 0) AS val FROM main_table a LEFT JOIN detail_table b ON a.id = b.fk
if no ▼
Matching rows only → multitablequerystrategies.html">INNER JOINSELECT a.*, b.col FROM table_a a JOIN table_b b ON a.id = b.fk

Step 4: Do I Need a Subquery?

After identifying your main pattern, check if a subquery is needed.

Does my calculation need a value from a DIFFERENT aggregation level or a different table I'm NOT joining to?

Examples:
• "percentage of total" (group count / global count)
• "above average" (row value vs. table average)
• "pre-aggregate then join" (summary + detail)
▼
Do I need a different aggregation level at all?
NO → No subquery needed — done!
if yes ▼
Can I use a window function instead?
(AVG() OVER(), SUM() OVER())
YES → Window function is cleaner — use thatAVG(val) OVER() AS overall_avg -- adds a column without collapsing rows
if no ▼
YES — YOU NEED A SUBQUERY. Where does it go?
▼
In SELECT
"Show a global value alongside each row"

Signal: percentage of total, ratioSELECT col, COUNT() 100.0 / (SELECT COUNT(*) FROM table) AS pct FROM table GROUP BY col
In WHERE
"Filter rows using a computed threshold"

Signal: above average, top performersSELECT * FROM table WHERE val > ( SELECT AVG(val) FROM table )
In FROM
"Pre-aggregate, then query the result"

Signal: rank groups, filter summariesSELECT * FROM ( SELECT col, COUNT(*) AS cnt FROM table GROUP BY col ) sub WHERE cnt > 5

Worked Examples: Walking the Tree

Example 1: Percentage of Users Registered per Contest

Problem: Find the percentage of total users registered in each contest, rounded to two decimal places. Tables: Users (userid, username) and Register (contestid, userid) Walking the tree: Step 1 — How many tables? Two (Users and Register) → Go to Step 2B Step 2B — Pick the JOIN: The output only needs contest_id and percentage — I don't need columns from Users, just a count. → No JOIN needed, but I need data from another table. Step 2C — Transformation: GROUP BY contest_id + COUNT per group → GROUP BY + aggregate Step 4 — Subquery? Formula is groupcount / totalcount * 100. Total comes from a different table at different grain. → Subquery in SELECT (denominator).

``sql
SELECT r.contest_id,
ROUND(COUNT(DISTINCT r.user_id)::numeric
/ (SELECT COUNT() FROM Users) 100, 2) AS percentage
FROM Register r
GROUP BY r.contest_id
ORDER BY percentage DESC, r.contest_id ASC;
`

Path: Step 1 (2 tables) → 2B (skip join) → 2C (GROUP BY) → 4 (subquery in SELECT)

Example 2: Restaurant 7-Day Moving Average

Problem: Compute the moving average of customer payments over a 7-day window (current day + 6 days before). Table: Customer (customerid, name, visitedon, amount) — one table Walking the tree: Step 1 — How many tables? One → Go to Step 2A Step 2A — Walk the checklist: - Just filtering? No. - String manipulation? No. - Involves dates? Yes → Step 3 Date Fork: What kind? Compare rows over time + range calculation → need date filtering (ROWS BETWEEN) + back to 2A. - Back in 2A: Running total / rolling window? YES → SUM/AVG OVER(ROWS BETWEEN). Key insight: Multiple customers per day means we must pre-aggregate daily totals first, then apply the window. `sql WITH daily AS ( SELECT visitedon, SUM(amount) AS daytotal FROM Customer GROUP BY visited_on ) SELECT visited_on, SUM(daytotal) OVER(ORDER BY visitedon ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS amount, ROUND(AVG(daytotal) OVER(ORDER BY visitedon ROWS BETWEEN 6 PRECEDING AND CURRENT ROW), 2) AS average_amount FROM daily ORDER BY visited_on OFFSET 6; ` Path: Step 1 (1 table) → 2A (dates → Step 3 → back to 2A → rolling window)

Example 3: Students and Examinations (CROSS JOIN + LEFT JOIN + COUNT)

Problem: Find how many times each student attended each exam. Must show 0 for exams not attended. Tables: Students, Subjects, Examinations — three tables Walking the tree: Step 1 — Three tables → Step 2B Step 2B — I need every student paired with every subject (including zeros). → CROSS JOIN (Students x Subjects) to generate all combos, then LEFT JOIN Examinations to count actuals. Step 2C — Transformation: COUNT per student-subject pair → GROUP BY + COUNT `sql SELECT s.studentid, s.studentname, sub.subject_name, COUNT(e.studentid) AS attendedexams FROM Students s CROSS JOIN Subjects sub LEFT JOIN Examinations e ON s.studentid = e.studentid AND sub.subjectname = e.subjectname GROUP BY s.studentid, s.studentname, sub.subject_name ORDER BY s.studentid, sub.subjectname; `` Path: Step 1 (3 tables) → 2B (CROSS JOIN + LEFT JOIN) → 2C (COUNT per group)

Final Takeaway

Every SQL problem breaks down into the same four questions:

1. How many tables? → Determines if you need a join
2. What join? → Match the relationship pattern to the right join type
3. What transformation? → Filter, aggregate, rank, compare, or label
4. Different grain? → If yes, you need a subquery (and now you know where it goes)

Practice walking the tree on every problem before writing code. After a few dozen problems, the routing becomes automatic.
